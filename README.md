# GwarnV1

Справочник уставов Arizona RP для MoonLoader. Команда открытия: `/gw`. Автор идеи: Ellis_Harris.

## Файлы

- `GwarnV1.lua` — интерфейс, поиск, локальное редактирование и проверка обновлений.
- `rules.json` — семь разделов с 566 статьями.
- `version.json` — текущая версия Lua и адрес файла для автообновления.

## Текущая версия: 1.2.9

- Enter в окне ID подтверждает выдачу и не передаёт нажатие игровому чату.
- Поле ID заново получает фокус при каждом открытии.
- Прозрачность фона по умолчанию — 25%; её можно изменить в настройках.
- Акцентный цвет применяется также к окнам редактирования и выдачи.

## Установка и проверка

Для текущей проверки в игре скопируй `GwarnV1.lua` и `rules.json` в папку MoonLoader. Открой справочник командой `/gw`.

После публикации `GwarnV1.lua`, `rules.json` и `version.json` в корне публичного GitHub-репозитория пользователю достаточно скачать Lua: при запуске скрипт загрузит `rules.json` и сохранит его рядом. Для проверки обновления самого Lua он читает `version.json`. Проверки запускаются при старте и повторяются раз в 6 часов; в настройках есть отдельные кнопки для проверки Lua и уставов.

Если на GitHub нет доступа или нужных файлов, скрипт продолжит работать с локальным `rules.json`. Пока файлы не опубликованы, удалённые проверки ожидаемо не пройдут.



## Даты в rules.json

У каждой организации есть поле `updated_at` в формате `YYYY-MM-DD`. Оно показывает дату последнего изменения базы этого раздела и отображается в окне. Верхнее поле `updated_at` — дата изменения всей базы. Эти даты ведутся в JSON и сами по себе не означают дату изменения устава на форуме.

Сейчас даты отмечают подготовку базы для скрипта: `2026-11-14`. Когда меняются статьи раздела, обновляются его `updated_at` и общая дата. Lua считывает их из JSON, поэтому для изменения даты править скрипт не нужно.

## Личные изменения

Добавленные, удалённые и изменённые через редактор статьи хранятся локально в `GwarnV1_custom.json` рядом со скриптом и применяются поверх загруженной базы. Этот файл остаётся на компьютере пользователя и не должен попадать в GitHub.

## Выпуск обновлений

1. Обновить статьи в `rules.json` и даты `updated_at` затронутых разделов.
2. При изменении Lua повысить версию в `script_version` и `SCRIPT_VERSION` в Lua-файле, затем указать ту же версию и точный адрес Lua в `version.json`.
3. Для обновления скрипта заменить `GwarnV1.lua` и `version.json` в корне ветки `main`. `rules.json` заменять, когда обновилась база уставов; если изменились Lua и правила, загрузить все три файла.

Когда найдена новая версия Lua, скрипт скачивает и проверяет её, сохраняет предыдущую копию как `.backup` и перезагружается.
